# OctoAcme Project Management Docs

This folder is the entry point for OctoAcme's project management guidance and the best starting place for onboarding to the team's delivery process.

## Process overview

### Lifecycle at a glance
- **Initiation:** define the problem, success metrics, stakeholders, initial risks, and a go/no-go decision.
- **Planning:** turn approved work into a prioritized backlog, milestones, dependencies, a Definition of Done, and an initial QA approach.
- **Execution:** move work through the project board, deliver in small pull requests, demo progress, and review risks regularly.
- **Release:** confirm acceptance criteria, CI and security checks, release notes, smoke tests, post-deploy verification, and rollback readiness.
- **Retrospective / improvement:** capture lessons learned, assign action items, and feed improvements back into the backlog.

### Roles and responsibilities
- **Project Managers:** coordinate plans, timelines, risks, dependencies, and status reporting.
- **Product Managers:** define outcomes, prioritize the backlog, and validate impact.
- **Developers:** design, build, test, document, and surface technical risks.
- **QA / Testing:** validate acceptance criteria, critical flows, and release readiness.
- **Stakeholders:** provide direction, approvals, and milestone feedback.

### Communication and quality
- **Cadence:** daily standups, weekly delivery or PM/Product syncs, milestone demos, and stakeholder updates.
- **Status updates:** use a project README or release document as the single source of truth for progress, risks, and decisions.
- **Escalation paths:** move blockers from team triage to PM/Product leadership and then sponsors when business impact grows.
- **Quality practices:** require automated tests, CI linting and security scans, issue-linked PRs with acceptance criteria, release checklists, smoke tests, post-deploy verification, and rollback readiness.
